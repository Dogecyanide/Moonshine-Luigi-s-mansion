# V2.0.0 Gate 2 Continuous Ghost Lab

**EXPERIMENTAL ONLY — NOT A RELEASE BUILD.** Gate 2 changes the ghost clock
lifecycle and introduces a new multi-stage file version. Back up
`susamune.ini`, `/susamune_ghosts`, and the current Homebrew Channel app before
testing.

Gate 2 starts from the tested V1.2.0 commit
`b6bc8747fa01f99ae8335390aaee6ddac768d4e8`. Ghost code has read-only access
to QFT's attempt serial, live QF, and stopped state. It does not write QFT
scratch, alter timing/capture hooks, change offsets, or reinterpret a result.

## What changed from Gate 1

- Saving during a live level exports the settled recording prefix. A Shine is
  no longer required.
- The opening pose is anchored at QF zero, so materialise-in time remains part
  of the stored duration. A live-prefix save can trail visible QFT by at most
  the three QF between four-QF transform samples.
- Course names use friendly episode labels, such as `Bianco Hills 4`, while
  unknown/internal starts keep a bounded raw fallback.
- One ghost may contain up to 64 route segments. Segments partition one
  absolute QFT timeline; they do not restart the ghost clock at an area load.
- A runner entering a later segment late sees the ghost already advanced by
  the same amount. A runner entering early sees no marker until the ghost's
  recorded entry QF. Time spent in stage loads remains a gap on the same
  timeline.
- Single-route recordings remain SGHF V1. Multi-stage recordings use SGHF V2
  with a fixed 2 KiB segment table inside the existing 512 KiB slot.
- Z on an occupied slot exports a friendly `.smsghost` share file. Z on an
  empty slot imports the fully validated fixed `inbox.smsghost`; import never
  overwrites an occupied slot.

The cyan collisionless marker remains the only ghost renderer. Shadow Mario,
Piantissimo, recorded animation state, deterministic input replay, and a
second interactive Mario remain deferred.

## PAL smoke pass

Keep QFT visible for every timing check.

1. Start Bianco Hills 4 and save to an empty ghost slot after roughly 30
   seconds without collecting a Shine. Load that slot, restart, and verify the
   marker races the saved prefix.
2. Compare the slot duration with visible QFT. The difference must be no more
   than three QF (about 25 ms); the previous multi-second missing-intro error
   must not return.
3. Instant Restart and Full Restart the route five times each. The previous
   attempt must become raceable. A ghost-only resync notice is acceptable;
   QFT itself must never change, freeze, or lose its exact result.
4. Collect a Shine during an ordinary run and shortly after entering a child
   stage. Both terminal results must save, reload, and end at QFT's exact
   stopped value.
5. Hold an actual fast-forward action during an attempt. That recording must
   be rejected as assisted; the selected library target and QFT remain intact.

## Continuous multi-stage pass

Use a parent/secret route whose QFT continues through the director change.

1. Record from the parent stage into the child stage, continue for at least 10
   seconds, then save without a Shine. The slot must contain one V2 ghost, not
   separate per-area ghosts.
2. Load it and repeat the route near the recorded pace. The marker disappears
   while its saved route does not match the live stage and reappears on the
   matching segment.
3. Enter the child roughly half a second late. On that segment the marker must
   already be roughly half a second ahead; it must not restart from the entry
   pose.
4. Enter roughly half a second early. The marker must remain hidden until its
   saved entry QF, then appear at the segment's first pose.
5. Restart during or immediately after the transition. The tentative segment
   must be rolled back as a restart, not appended to the previous ghost.
6. Collect the Shine during the transition's 30-observation classification
   window. The final segment and exact QFT result must still be retained.
7. Repeat a route that visits the same area more than once. Playback must pick
   the occurrence containing the current absolute QF rather than the first
   matching area ID.

## Share round trip

Share files live on the device from which the launcher was started:

`/susamune_ghosts/share/<region>/p<profile>`

1. Select an occupied slot and press Z. Export creates a filename shaped like
   `2026_08_15_BH4_42490[89ABCDEF].smsghost`: export date, bounded route code,
   compact `MSSmmm`/`SSmmm` time, and the canonical file CRC.
2. Copy that file off the SD and validate/watch it as a canonical SGHF file.
   The friendly filename is presentation only; the SGHF header and checksums
   remain authoritative.
3. To import, place a received file in the selected profile directory and
   rename it exactly `inbox.smsghost`.
4. Select an empty slot in that same profile and press Z. After refresh, load
   and race the imported slot.
5. Confirm import refuses a corrupt file, a forward version, the wrong region,
   the wrong profile, and an occupied destination without changing the current
   race target or library.
6. Export the imported slot. Its canonical bytes and CRC must survive the
   round trip.

## Limits and failure behaviour

- The 15-minute limit applies to the whole continuous ghost, not each segment.
  At 107,892 QF the recorder retains the exact cap prefix, shows a one-time cap
  notice, and stops adding samples. Gameplay and QFT continue. A later Shine
  does not extend that prefix; it remains manually saveable as incomplete.
- The first limit reached wins: 15 minutes, 26,974 samples, or 64 segments.
- Each profile still allows 48 occupied slots and ten aggregate hours.
- Occupied slots cannot be overwritten. Delete first, wait for refresh, then
  save or import.
- SAVE/DELETE/IMPORT use the existing A/B header-last journal. Interrupted
  work may leave the older generation active, never a trusted partial file.
- SD removal reports an I/O error and preserves volatile tracks and existing
  persistence. Hot reinsertion is not promised in this gate; reboot the
  launcher before retrying storage.

## Regression pass

- Preserve all V1 SGHF library entries; load and race at least one Gate 1 file.
- Cycle all four PB profiles and confirm settings, binds, PBs, Records, and
  global progress are unchanged.
- Save/load a savestate ten times. Volatile recording is discarded; a pinned
  target survives and resynchronizes. A stale asynchronous load is ignored.
- Open every menu tab and Creation editor while recording and replaying.
- Repeat Fast Text, QFT, Shine/death/boss, reset-button, launcher, ISO-on-other-
  device, write-protected/full-media, and A/B interruption tests on PAL.
- Run the regional parity pass on JP and US only after PAL is stable. Sharing
  is same-region only; Gate 2 does not convert route IDs across revisions.

The three-person regression pass remains required before treating any Gate 2
result as release evidence.

## Final build budget

The runtime reservation remains exactly three 512 KiB MEM2 slots (1.5 MiB):
recording, playback, and the ARM/PPC transfer mailbox. The 64 descriptors use
the last 2 KiB already inside each track slot. The savestate window, ordinary
heap, stage heap, settings/PBs/Records ranges, and QFT scratch are unchanged.

| Build | JP raw / manifest | US raw / manifest | PAL raw / manifest | Free JP / US / PAL |

| Console | 160,996 / 161,164 | 160,852 / 161,020 | 160,924 / 161,092 | 363,228 / 363,372 / 363,300 |
| Dolphin | 145,508 / 145,676 | 145,304 / 145,472 | 145,440 / 145,608 | 378,716 / 378,920 / 378,784 |

Free space is measured against the padding-free `0x7ffc0` raw-blob ceiling.
The manifest adds its fixed header and 17 regional writes; unused capacity is
not emitted. The HBC package includes all three regional manifests and this
testing guide.
