# V2.0.0 Gate 1 Ghost Storage Lab

**EXPERIMENTAL ONLY — NOT A RELEASE BUILD.** This test package deliberately
exercises new MEM1, MEM2, QFT-read, and SD-storage paths. Back up
`susamune.ini` and the `/susamune_ghosts` directory before testing.

Gate 1 starts from the exact V1.2.0 tested commit
`b6bc8747fa01f99ae8335390aaee6ddac768d4e8`. QFT remains the authority: ghost
code reads its attempt serial, live QF, and stopped state, but does not modify
QFT timing, capture hooks, offsets, results, or scratch state.

## Scope

- Padding-free 512 KiB MEM1 mod region with a `0x82000` arena reserve.
- Collisionless transform recording at one sample per four QF.
- Cyan visual race marker with four opacity choices.
- Conservative ghost-only clock synchronization. Playback stays on its first
  pose until 30 monotonic observations have established the post-reset epoch;
  a later backward edge rewinds and resynchronizes the ghost only.
- Exact completed-run boundaries. If QFT finishes between recorded samples,
  the terminal pose is interpolated from already-recorded poses.
- 15 minutes per ghost, 48 fixed slots per PB profile, and 10 hours total per
  profile. Both limits are enforced.
- Console-only asynchronous SD library under
  `/susamune_ghosts/<jp|us|pal>/p0..p3`, with fixed A/B generations,
  header-last commits, CRC validation, tombstone deletion, and 16 KiB maximum
  I/O per DI-idle service pass.
- Versioned, big-endian SGHF V1 share files. Gate 1 stores canonical SGHF bytes
  inside its recovery envelope; arbitrary host import/export UI is deferred.

Dolphin records and races volatile ghosts, but intentionally reports the SD
library unavailable. A second interactive Mario, animation/model replay,
deterministic input replay, compression, multi-stage routes, and cross-region
conversion are not in Gate 1.

## First PAL pass

Use PAL first. Keep QFT visible throughout the clock tests.

1. Cold boot, start a normal attempt, and wait for the `GHOST TEST: synced`
   diagnostic. QFT must continue advancing normally.
2. Restart the same route. Confirm `GHOST TEST: previous attempt ready` and a
   cyan marker. The marker waits at its first pose during synchronization, then
   advances against the unchanged QFT clock.
3. Repeat Instant Restart and Full Restart at least five times each. A
   `late QFT rebase` diagnostic is acceptable in this experimental build; a
   changed QFT result, frozen timer, or missing attempt edge is not.
4. Complete attempts by collecting a Shine at several durations. The stored
   result must equal QFT's result and the marker must not teleport to a
   next-frame or post-Shine pose.
5. Load a library target and run a challenger. The pinned target must survive
   restarts. A completed challenger is retained until it is saved or the pin is
   released; it must not be silently overwritten.

## Storage pass

- Cycle all four PB profiles and refresh each catalog.
- Save short, medium, and 15-minute-cap recordings into empty slots.
- Load every saved recording, restart its exact route, and verify playback.
- Confirm an occupied slot cannot be overwritten directly. Delete it first,
  wait for the refreshed empty catalog, then save.
- Pull power or reset during the payload phase of a disposable SAVE. On the
  next boot, the older complete generation must load and the incomplete bank
  must not become active.
- Repeat during DELETE; either the old ghost or the tombstone may win, never a
  partial canonical file.
- Test full, write-protected, and temporarily removed media. The current race
  target and settings/PBs/Records must remain intact.
- Corrupt one disposable bank and confirm the other valid generation remains
  loadable. A recognized forward-version envelope must make the profile
  read-only rather than being treated as empty.
- Run with an ISO on the other device from the launcher. Ghosts must still use
  the launcher's device, while disc reads remain stable.

## Regression pass

- Open every menu tab and Creation editor while recording and replaying.
- Hold both fast-forward binds. Eligibility changes only when the actual
  director-budget patch ran; merely entering a Creation editor while holding
  the combo must not discard a normal-speed recording.
- Save and load a savestate ten times. Current recording is discarded. A pinned
  library target remains available, resynchronizes against restored QFT, and a
  stale pre-load asynchronous LOAD response is ignored.
- Enter a secret or child area. Gate 1 must explicitly refuse unsupported
  multi-stage recording; it must not show a stale route ghost.
- Repeat V1.2 Fast Text, parent/secret QFT, Shine, death, boss, reset-button,
  settings, binds, PB, Records, progress-persistence, and launcher tests on PAL,
  then JP and US.

## Memory and disk budget

The runtime ghost reservation is exactly 1.5 MiB of post-loader MEM2: one
512 KiB record slot, one playback slot, and one ARM/PPC transfer slot. The
existing 16 MiB savestate window is unchanged. No stage-heap or ordinary-heap
ghost library is allocated.

The final Gate 1 build budgets are:

| Build | JP raw / manifest | US raw / manifest | PAL raw / manifest | Free JP / US / PAL |
|---|---:|---:|---:|---:|
| Console | 154,340 / 154,508 | 154,192 / 154,360 | 154,272 / 154,440 | 369,884 / 370,032 / 369,952 |
| Dolphin | 141,308 / 141,476 | 141,108 / 141,276 | 141,244 / 141,412 | 382,916 / 383,116 / 382,980 |

Free space is measured against the `0x7ffc0` raw-blob ceiling. The manifest is
168 bytes larger because it also carries the fixed header and regional hook
writes.

Raw SGHF payload costs about 479.5 bytes/s, 28.8 KiB/min, or 1.73 MiB/hour.
Ten live hours are about 17.3 MiB per profile. A/B recovery can retain about
34.6 MiB/profile in the absolute worst case, or about 414 MiB for all four
profiles across all three regions. These are SD limits, not runtime MEM2 use.

The historical 500 KiB pressure padding is absent. Unused executable capacity
is not emitted into `mod_<region>.bin`.
