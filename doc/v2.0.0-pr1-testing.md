# Susamune V2.0.0 "Ghosts of Delfino" Pre-release 1 Testing / テストガイド

## Overview (English)

**EXPERIMENTAL TEST BUILD — NOT A RELEASE CANDIDATE.** The internal version is
`2.0.0-pre.1`. This build deliberately exercises new MEM1, MEM2, rendering,
cross-region, and SD-card paths. A successful run is evidence for the next
prototype, not a promise that the feature is ready to ship.

Pre-release 1 is based on the official V1.2.0 release, not the earlier RC1
snapshot used by the Gate builds. Back up `susamune.ini`, Susamune PB and
progress journals, and the existing Homebrew Channel app before installing.
For this test, remove the old experimental `/susamune_ghosts` directory and
start with a clean one. Do not delete the V1.2.0 settings, PB, Records, or
progress files.

The distributed `susamune_launcher.zip` must contain one
`susamune_launcher/` app directory with `boot.dol`, `mod_jp.bin`,
`mod_us.bin`, `mod_pal.bin`, `meta.xml`, `icon.png`, and this guide as
`TESTING.md`. The Homebrew Channel and launcher must identify the package as
`Susamune Launcher SIGMA` and
`V2.0.0 "Ghosts of Delfino" Pre-release 1`. If either still says Gate 2,
Trial By Sunshine, or plain Susamune Launcher, stop: the wrong package is
installed.

## Safety boundaries (English)

- Keep QFT visible during every timing test. Ghost code may read QFT's attempt
  serial, live QF, stopped state, and final result. It must not write QFT state
  or alter QFT timing/capture code. Any changed QFT result is a hard failure.
- The renderer is a visual-only, collisionless, cyan Shadow-Mario-shaped
  prototype. It is not retail Shadow Mario enemy AI and does not claim retail
  material or animation parity. Its J3D model allocations live in a fixed
  private 88 KiB MEM2 heap. The scene owns only its bounded registration node;
  repeated stage loads must not leak or grow system/stage-heap use. If the
  model cannot initialize safely, the expected fallback is the cyan 2D marker.
- A ghost remains limited to 15 minutes across its entire continuous route.
  Hitting the limit stops recording samples; gameplay and QFT continue.
- Each personal profile exposes exactly 45 slots: zero-based slots `0..44`,
  shown in the UI as `01..45`. Old experimental zero-based entries `45..47`
  are ignored, excluded from the ten-hour quota, and are not readable or
  deletable in this build. Wipe the old experimental ghost directory before
  testing.
- Pre-release 1 exposes one global 12-entry imported-ghost pool. It is
  independent of all four PB profiles and does not consume their personal
  slot or ten-hour quotas.
- Occupied personal entries are never overwritten. Delete first, wait for
  storage to finish, then save.
- SD access remains serialized behind the async-DI guard. Never interpret a
  temporarily delayed list/save as permission to issue the same operation
  repeatedly.
- Do not replace an imported file out-of-band between scanning and loading or
  deleting it. After changing the import folder externally, reboot or rescan
  before acting on a row; hot-swap identity is outside this prototype.

## 安全上の境界（日本語）

- すべての計測テストで QFT を表示したままにしてください。ゴーストコードが
  読み取ってよいのは、QFT の試行シリアル、現在の QF、停止状態、最終結果
  です。QFT の状態を書き換えたり、QFT の計測・キャプチャコードを変更したり
  してはいけません。QFT の結果が変化した場合は重大な失敗です。
- 描画物は、見た目だけの、当たり判定を持たない、シアン色の
  Shadow Mario 形状プロトタイプです。製品版 Shadow Mario の敵 AI ではなく、
  製品版と同一のマテリアルやアニメーションを保証するものでもありません。
  J3D モデルの割り当ては、固定された専用 88 KiB MEM2 ヒープ内に置かれます。
  ステージ側が所有するのは上限の決まった登録ノードだけです。ステージ読み込み
  を繰り返しても system/stage heap の使用量が増加したりリークしたりしては
  いけません。モデルを安全に初期化できない場合は、シアン色の 2D マーカーへ
  フォールバックするのが正常です。
- 1 つのゴーストは、連続するルート全体で最大 15 分です。上限に達すると
  サンプル記録だけが停止し、ゲームプレイと QFT は継続します。
- 各個人プロファイルで使用できるスロットは正確に 45 個です。ゼロ始まりでは
  `0..44`、UI 表示では `01..45` です。古い実験版のゼロ始まりエントリ
  `45..47` は無視され、10 時間のクォータにも含まれず、このビルドから
  読み込み・削除することもできません。テスト前に古い実験用ゴースト
  ディレクトリを消去してください。
- Pre-release 1 には、全体で共有する 12 エントリのインポートゴーストプールが
  1 つあります。これは 4 つの PB プロファイルすべてから独立しており、個人
  スロット数や 10 時間クォータを消費しません。
- 使用済みの個人エントリは絶対に上書きされません。先に削除し、ストレージ
  処理の完了を待ってから保存してください。
- SD アクセスは引き続き async-DI ガードの内側で直列化されます。一時的に
  一覧表示や保存が遅れても、同じ操作を繰り返し要求してよいという意味では
  ありません。
- スキャンと読み込み／削除の間に、インポートファイルを外部から置き換えないで
  ください。インポートフォルダを外部で変更した後は、行を操作する前に再起動
  または再スキャンしてください。hot-swap identity は本プロトタイプの対象外
  です。

## Common preflight (English)

1. Extract the unmodified `susamune_launcher/` directory from
   `susamune_launcher.zip` to the Homebrew Channel apps directory. Confirm it
   contains `boot.dol`, `mod_jp.bin`, `mod_us.bin`, and `mod_pal.bin`. Use
   that same app for JP, US, and PAL; do not mix binaries from different
   packages.
2. Boot an existing V1.2.0 setup. Confirm all settings and binds retain their
   values, all four PB profiles remain selectable, Records still contains 123
   achievements, and prior unlock/statistics/progress data is intact.
3. Open every menu tab once. Confirm ghost visibility/opacity settings work and
   the Ghosts tab lists 45 personal entries separately from the shared
   12-entry imported pool.
4. Make exactly one import folder, `/susamune_ghosts/import/`, on the
   launcher's device. Drag and drop files into it under arbitrary original
   filenames; do not rename them to an inbox or slot name. Select
   `Scan import folder`, or press `Y` while the imported section is selected,
   to rescan. Only bounded, validated `.smsghost` files may appear in game.
5. Start with no pinned ghost. Record 30–60 seconds, select an empty personal
   entry, and verify the menu asks `Save [name]?`. `B` must cancel without
   I/O; `A` must save the currently named recording. If the logical save
   source changes on the confirmation frame, the first `A` must refuse and
   require confirmation again with the new name.

## PAL hardware pass — GMSP01 (English)

PAL is the primary gameplay pass because its tester is most familiar with the
revision. Record the observed QFT result and exported CRC for every exchange
candidate.

1. Boot GMSP01 from its normal source. Confirm the launcher selects PAL and the
   game reaches gameplay with no heap/canary warning.
2. Record Bianco Hills 4 from its normal parent start, collect the Shine, save,
   reload, and race it. The friendly route name, saved milliseconds, duration,
   and visual pace must agree with the original run.
3. Record Sirena 4 through beach → hotel → casino → secret. Enter one child
   roughly half a second behind the ghost and another roughly half a second
   ahead. The ghost must retain one absolute QFT timeline: it is already ahead
   in the first case and appears later in the second, never restarting as a
   segment ghost.
4. Start directly inside the Pianta 5 secret and Bianco 3 secret. Neither save
   prompt, library row, nor exported filename may say raw `Area 42`,
   `Area 47`, or an incorrect episode. Record the exact friendly labels shown.
5. Pin and race an existing ghost, then begin a new attempt in a different
   level. Save the new attempt to an empty entry. The confirmation name and
   stored route must describe the challenger/new recording, never the pinned
   playback ghost. Reload both entries to prove neither changed identity.
6. Repeat step 5 with a completed challenger, a partial mid-level challenger,
   and immediately after a child-stage transition. Saving must always prefer
   the current saveable recording over playback.
7. Save, load, Instant Restart, Full Restart, pause, warp, and collect a Shine
   while racing. The cyan Shadow-Mario-shaped prototype must remain
   collisionless, follow the recorded transform, and reinitialize without a
   system/stage-heap leak. Do not evaluate it as retail Shadow Mario AI or
   retail material parity. Test all opacity choices while overlapping Mario,
   in fog/water, and in front of/behind scenery; report opaque, partial-tint,
   or Z-order anomalies. If it falls back to the cyan 2D marker, record the
   area and whether playback otherwise remained valid.
8. Load a savestate ten times while recording and racing. Volatile recording
   state must follow the documented savestate policy, the pinned target must
   resynchronize safely, and QFT must preserve its exact values.
9. Use speedup during a fresh attempt. The attempt must be rejected as
   assisted without changing the selected library entry or QFT.
10. Fill/test enough entries to cross personal pagination, then delete and
    reuse entries. Confirm exactly 45 personal entries are accessible, no
    occupied entry can be overwritten, and profiles remain isolated.
11. Export one single-stage and one multi-stage PAL file with friendly names,
    for example `2026_08_15_BH4_42490[89ABCDEF].smsghost`. Copy both into
    `/susamune_ghosts/import/` under arbitrary unchanged filenames for the JP
    tester.

## JP hardware pass — GMSJ01 (English)

Use the same launcher package and a clean boot before this pass. Do not reuse a
savestate across regions; savestates remain region-specific even though visual
ghost files are portable.

1. Boot GMSJ01 from its normal source. Confirm the launcher selects JP and the
   official V1.2.0 settings, profiles, Records, and progress survived exactly
   as in the common preflight.
2. Repeat the Bianco Hills 4 parent-route, direct-start Pianta 5 secret, and
   direct-start Bianco 3 secret checks from the PAL pass. Friendly identity and
   episode mapping must be equivalent despite revision-specific hook addresses.
3. Record and replay a JP multi-stage route. Confirm early/late child entry,
   pause/restart/warp behavior, final milliseconds, and Shadow-Mario-shaped
   prototype/cyan 2D fallback behavior match the PAL rules.
4. With a JP ghost pinned, record and save a different route. Confirm the
   prompt and saved bytes identify the new challenger rather than the pinned
   playback ghost. Repeat once with a partial recording.
5. Put the two unchanged PAL `.smsghost` files from the PAL pass into
   `/susamune_ghosts/import/` under their arbitrary existing filenames. Select
   `Scan import folder`. Both valid files must appear without an inbox rename,
   copying into a personal slot, or changing the active JP PB profile.
6. Race both PAL files on JP. Route validation must accept known portable
   parent/child identities, preserve the absolute QFT timeline, and render the
   same path. Record the live JP QFT comparison at parent entry, child entry,
   and finish.
7. Corrupt a copy's header, truncate another copy, give one a forward format
   version, and place a non-ghost file in the import directory. None may become
   raceable; valid imported entries and personal profiles must remain intact.
   A forward-version file must remain on SD but be omitted from the old build.
   A supported-version file found corrupt only during full-load validation
   becomes a visible unsafe/quarantined row; `X` must delete only that imported
   source file safely.
8. Place more than 12 valid files in the import directory. The UI must report
   the bounded-capacity condition deterministically; it must not depend on FAT
   directory order, overflow the mailbox, or silently expose an unvalidated
   thirteenth entry.
9. Delete one imported entry from the shared pool. It must remove only the
   selected imported file, not a personal ghost or a same-named file outside
   the fixed import directory.
10. Export one JP single-stage and one JP multi-stage file and pass them back
    unchanged to the PAL tester.

   したインポートファイルだけであり、個人ゴーストや、固定インポート
   ディレクトリ外にある同名ファイルを削除してはいけません。
10. JP の単一ステージファイルと複数ステージファイルを 1 つずつエクスポート
    し、変更せずに PAL テスターへ返します。

## Two-way cross-region validation (English)

1. On PAL, select `Scan import folder` for
   `/susamune_ghosts/import/` and race both JP exports without renaming them.
   Compare the recorded CRCs and route labels with the JP notes.
2. In each direction, deliberately try a foreign file with an unknown game ID,
   invalid region/revision pair, invalid parent for a child area, or disallowed
   route flags. It must be refused before playback.
3. Same-region personal experimental routes may retain their existing
   structural compatibility, but foreign files must pass the stricter portable
   route table for the header and every multi-stage segment.
4. Imported ghosts are one global 12-entry view. Switching among the four PB
   profiles must not duplicate, hide, renumber unpredictably, or take ownership
   of imported files.
5. Export must use create-new (`FA_CREATE_NEW`) behavior. If the generated
   pathname already exists, it must report `Export filename already exists`
   and leave that file untouched. It must not read or compare the existing
   file's bytes before refusing; identical content does not turn the refusal
   into success, and different content is never overwritten.

## 双方向リージョン間検証（日本語）

1. PAL 側で `/susamune_ghosts/import/` に対して `Scan import folder` を
   選択し、JP の 2 つのエクスポートを改名せずにレースします。記録した CRC と
   ルートラベルを JP 側の記録と比較してください。
2. 双方向それぞれで、未知の game ID、不正な region/revision の組み合わせ、
   子 area に対する不正な parent、または禁止された route flags を持つ他
   リージョンのファイルを意図的に試します。再生前に拒否されなければなりません。
3. 同一リージョンの個人実験ルートは既存の構造的互換性を維持してよい一方、
   他リージョンのファイルは、ヘッダーと複数ステージの全 segment について、
   より厳格な portable route table を通過しなければなりません。
4. インポートゴーストは 1 つの全体共有 12 エントリ表示です。4 つの PB
   プロファイルを切り替えても、インポートファイルが重複、非表示、予測不能な
   再番号付け、またはいずれかのプロファイル所有になってはいけません。
5. エクスポートは create-new（`FA_CREATE_NEW`）動作を使用します。生成される
   pathname がすでに存在する場合は `Export filename already exists` と報告し、
   既存ファイルを変更してはいけません。拒否前に既存ファイルのバイト列を
   読み取ったり比較したりしてはいけません。同一内容でも成功扱いにはならず、
   異なる内容も絶対に上書きされません。

## Storage and interruption checks (English)

- Remove the SD card while idle, then request a refresh. An I/O error is
  expected. Hot reinsertion is not promised; reboot the launcher before
  expecting storage to recover.
- Test write-protected and nearly full media. A failed save/export/delete must
  preserve the prior valid journal generation and current playback target.
- Interrupt one personal SAVE and DELETE operation, then reboot. Header-last
  A/B journaling must expose either the old valid state or the completed new
  state, never a trusted partial entry.
- Interrupt import enumeration and imported-file deletion separately. No path
  outside `/susamune_ghosts/import/` may change.
- Confirm gameplay and disc streaming continue normally while large ghosts are
  validated in bounded chunks.

## ストレージおよび中断テスト（日本語）

- 待機中に SD カードを抜き、その後 refresh を要求します。I/O error が出るのが
  正常です。再挿入後の即時復帰は保証されません。ストレージの復帰を期待する
  前にランチャーを再起動してください。
- 書き込み禁止メディアと、空き容量がほとんどないメディアをテストします。
  保存・エクスポート・削除に失敗しても、以前の有効な journal generation と
  現在の再生対象が維持されなければなりません。
- 個人 SAVE と DELETE をそれぞれ 1 回中断し、その後再起動します。ヘッダーを
  最後に書く A/B journaling により、以前の有効状態または完了した新しい状態の
  どちらかだけが公開され、途中のエントリが信頼済みとして扱われてはいけません。
- インポート列挙とインポートファイル削除を別々に中断します。
  `/susamune_ghosts/import/` の外にある path が変更されてはいけません。
- 大きなゴーストを上限付き chunk で検証している間も、ゲームプレイと disc
  streaming が正常に継続することを確認します。

## Three-person regression pass (English)

Pre-release 1 does not become release evidence until three people complete a
coordinated pass: a PAL tester, a JP tester, and a third tester independently
repeating the failure-prone cases (US may be used for this third regional
check). At minimum, all three must verify:

- QFT start, live display, loading-zone continuity, stopped result, leading
  zero setting, and capture behavior against V1.2.0. Record exact before/after
  values; “looks close” is not sufficient.
- Shine, death, boss, blue-coin, NPC interaction, pause, restart, warp,
  savestate, reset-button, Fast Text, and fast-forward rejection paths.
- V1.2.0 settings, binds, PBs, Records, statistics, achievements, and progress
  preservation across reboot and profile changes.
- Personal save/load/delete, save confirmation/cancellation, pinned-ghost save
  arbitration, imported-pool refresh/delete, arbitrary filenames, corruption
  refusal, and two-way cross-region playback.
- The visual-only cyan Shadow-Mario-shaped prototype's visibility/opacity,
  collisionlessness, stage reinitialization, private MEM2 bounds, cyan 2D
  fallback, and bounded/non-leaking system/stage-heap behavior. Do not score
  retail enemy AI, material, or animation parity.

Any QFT regression, cross-region route confusion, write outside the fixed
ghost directories, occupied-entry overwrite, unbounded or leaking
gameplay-heap consumption by the renderer, or unexplained console hang blocks
the next build.
