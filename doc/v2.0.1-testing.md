# Susamune V2.0.1 "Ghosts of Delfino" Testing / テストガイド

## English

This is the focused acceptance pass for the V2.0.1 hotfix. Back up
`susamune.ini`, Records/PB data, both ghost folders, theme assets, and BGM before
testing. Install all eight files from one package together and confirm both the
Homebrew Channel and launch screen show `Susamune Launcher` and
`V2.0.1 "Ghosts of Delfino"` with one matching Build ID.

### Gate 1: Yoshi crash and V4 capture

1. On JP, replay the exact ghost that produced `susamune_crash_b.txt` and reach
   its Yoshi-mount frames. The game must not raise a DSI; unsupported sentinel
   poses may briefly use the normal marker fallback.
2. Repeat one Yoshi-mount Race or Watch smoke on PAL and US. Regress ordinary
   animations, Watch 1, and Watch 2.
3. Record and save one run while mounted on each available Yoshi colour and one
   run that carries a normal takeable object. Reload and race each file.
4. Validate a newly saved file with `scripts/validate_ghost.py`. It must report
   version 4 and valid attachment metadata. Confirm an established V3 file
   still loads and races unchanged.
5. Record more than seven distinct held identities if a safe test route is
   available. The file must remain valid and report held-object overflow rather
   than stopping the recording.

V4 captures attachment state for future rendering; this build is not expected
to draw Yoshi or held-object models.

### Gate 2: PB ghost save policy

1. Confirm `PB ghost save` offers exactly `Ask`, `Auto-Save`, and `Don't ask`,
   defaults to `Ask`, and persists independently for JP, US, and PAL.
2. In `Ask`, earn a PB and trigger a normal restart/departure. A must open the
   exact PB save flow. Return and press B: the action must continue without a
   save, and the completed ghost must remain available as the automatic race
   target or for a later manual save.
3. If two protected PB tracks exist, resolve them one at a time. Neither A nor B
   may silently resolve the other token.
4. In `Auto-Save`, earn a PB with an empty Personal slot. It must save to the
   first empty slot, wait for success, and only then continue. A failed request
   must return to `Ask` with the PB protected. During an automatic wait, a fresh
   B must also return to `Ask` without releasing the held action.
5. In `Don't ask`, earn a PB and restart. No protection prompt may appear, and
   the completed track must not be immediately erased.
6. Repeat a protected title/Exit/natural departure and savestate-load prompt
   with Disable Warps enabled. The menu and binds must never lock. Loading an
   older savestate necessarily ends the current volatile ghost; save or cancel
   the load when it must be kept.

### Gate 3: full library and deletion

Use a backed-up or expendable profile.

1. Fill or stage all 45 writable Personal slots, then trigger a protected PB
   save. `Auto-Save` must fall back to `Ask`; no existing slot may be overwritten.
2. From the full-library screen, move between slots, press X, and confirm the
   `Delete ghost from SD?` panel appears. B must cancel without mutation.
3. Repeat, press A, and wait for the delete acknowledgement. The catalog must
   refresh and offer that exact newly empty slot; saving must still require its
   own A confirmation.
4. In ordinary Personal and Imported browsing, X must show the same A Yes/B No
   confirmation. Unsafe Personal entries must not be deletable. Quarantined or
   forward-version Imported files must remain visible and become deletable only
   after that explicit confirmation.

### Gate 4: vertical observer camera

1. Watch one ghost on a route with a sustained climb and descent. The camera
   must follow vertically instead of accumulating lag until it points upward.
2. Repeat with Watch 2, including a pair that separates vertically. Horizontal
   framing remains retail and may choose one runner when the pair is far apart;
   vertical drift must not accumulate.
3. Exit with fresh B and fresh Start, complete a Watch naturally, and force one
   safe route failure. Each must restore a visible, controllable Mario and a
   normal camera without a permanent Y offset.
4. Regress direct-secret and parent-to-secret Watch, including B/Start used to
   skip each opening cutscene.

### Gate 5: release regressions

1. Enter Bianco 4, Bianco 5, and Pianta 5 through retail Shine Select.
2. Recheck normal Race/Watch/Watch 2, PB saving and lifetime ghost statistics,
   QFT timing, achievements, Warp Wheel, instant/full restart, savestate save
   and load, custom theme/BGM, and all three regions' existing configuration.
3. Confirm no temporary `GHOST TEST` or model-loader diagnostics returned.

If the Wii raises a hard exception, leave the crash screen visible for about
five seconds before power-off. Preserve the newest matching
`susamune_crash_a.txt/.bin` or `susamune_crash_b.txt/.bin` pair from the root of
the device that launched Susamune.

## 日本語

これは V2.0.1 hotfix の focused acceptance test です。`susamune.ini`、Records／PB、両 ghost
folder、theme、BGM を backup し、同じ package の 8 files を一緒に導入してください。Homebrew
Channel と launch screen が `Susamune Launcher`、`V2.0.1 "Ghosts of Delfino"`、同じ Build ID
を表示することを確認します。

### Gate 1: Yoshi crash／V4

1. JP で `susamune_crash_b.txt` を発生させた同じ ghost を再生し、Yoshi mount frame まで進めます。
   DSI が起きないこと。unsupported sentinel pose は marker fallback でも構いません。
2. PAL／US でも Yoshi mount の Race または Watch を 1 回ずつ行い、通常 animation、Watch 1／2 も
   regression test します。
3. 各 Yoshi 色の搭乗中、および通常の object を持った run を記録・保存し、reload／Race します。
4. 新しい file を `scripts/validate_ghost.py` で確認し、V4 attachment metadata が valid であること。
   既存 V3 file も従来通り load／Race できること。
5. 安全な route があれば 7 種類を超える held identity を記録し、recording failure ではなく
   held-object overflow として valid file になること。

V4 は将来の rendering 用 data を保存します。この build では Yoshi／held model の描画は未実装です。

### Gate 2: PB ghost save policy

1. `PB ghost save` が `Ask`／`Auto-Save`／`Don't ask` の 3 choice で、default `Ask`、region ごとに
   persistence すること。
2. `Ask` で PB 後に通常 restart／departure を行います。A は exact PB save を開き、B は save せず
   続行します。B 後も completed ghost が auto race target または manual save に使用できること。
3. protected PB が 2 個ある場合は 1 token ずつ処理されること。
4. `Auto-Save` は最初の空き Personal slot に save ACK 後だけ続行すること。failure／timeout と
   fresh B は PB と action を保持して `Ask` に戻ること。
5. `Don't ask` では prompt を表示せず、completed track を即時削除しないこと。
6. Disable Warps 中も title／Exit／natural departure／savestate load の protected flow が lock しない
   こと。古い savestate load は volatile ghost を終了するため、必要なら先に save または load cancel
   してください。

### Gate 3: full library／delete

backup 済み profile で 45 Personal slot を埋め、protected save を開始します。overwrite せず Ask に
戻ること。slot で X を押すと `Delete ghost from SD?` が表示され、B は cancel、A は delete ACK 後に
catalog refresh、新しく空いた同じ slot を save 候補にすること。通常 Personal／Imported も X の後に
A Yes／B No confirmation が必要です。unsafe Personal は delete 不可ですが、quarantine／future
Imported file は visible のまま、同じ明示 confirmation 後だけ delete 可能であること。

### Gate 4: vertical camera

大きく上昇／下降する route を Watch 1 と Watch 2 で確認し、camera の vertical lag が累積して真上を
向かないこと。fresh B／Start、natural finish、safe route failure の後に visible／controllable Mario
と通常 camera が戻ること。direct secret、parent-to-secret、intro の B／Start skip も再確認します。

### Gate 5: regression

retail Shine Select から Bianco 4／5、Pianta 5 に入り、通常 Race／Watch、PB save／lifetime stats、
QFT、achievement、Warp Wheel、restart、savestate、theme／BGM、JP／US／PAL 設定を smoke-test します。
一時 `GHOST TEST`／model-loader diagnostic が戻っていないこと。

hard exception 時は約 5 秒待って power-off し、launcher device root の最新
`susamune_crash_a.txt/.bin` または `susamune_crash_b.txt/.bin` pair を保存してください。
