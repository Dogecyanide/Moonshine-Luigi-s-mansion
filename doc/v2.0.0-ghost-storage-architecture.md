# V2 ghost storage architecture

Status: experimental V2 infrastructure. This is not a release commitment.

## Safety boundary

QFT remains the clock authority. Ghost code may read the current QF and attempt
serial, but must not write QFT scratch, alter hooks, change capture cadence, or
reinterpret a final result. A clock discontinuity discards tentative ghost
samples or starts a new ghost epoch; it never repairs QFT.

The PPC mod does not perform file I/O. The Nintendont ARM kernel owns FatFS and
services ghost requests only from the existing main-loop branch where no async
DI read is active. File work is chunked so a large ghost cannot monopolise ISO
streaming.

## Runtime memory

Console reuses the loader-only `0x91780000-0x91900000` buffer after boot:

| Range | Size | Runtime owner |
|---|---:|---|
| `0x91780000-0x91800000` | 512 KiB | active recording |
| `0x91800000-0x91880000` | 512 KiB | active visual playback |
| `0x91880000-0x91900000` | 512 KiB | ARM/PPC transfer mailbox |

The transfer slot reserves its first `0x100` bytes for two cache-line-owned
control records and protocol headroom. Its remaining `0x7ff00` bytes hold one
canonical ghost file or the 48-entry catalog response. No whole library is ever
held in MEM2, MEM1, the system heap, or the stage heap.

Dolphin keeps the same three-slot shape at `0x71000000-0x71180000`. Its visual
recorder can use those slots, but the ARM storage protocol is console-only.
Host-file persistence is a separate platform feature and must fail closed until
implemented.

## Library limits

The personal namespace remains `(game region, PB profile)`. Each of JP, US,
and PAL has the four existing PB profiles. Every namespace is subject to both
limits:

- 45 writable ghost rows (`0..44`).
- 10 hours of aggregate recorded QFT duration.

Rows `45..47` are outside the PR1 personal namespace. The 48-row wire response
keeps three zero tail rows for ABI convenience, but ARM does not scan the old
files, excludes them from count/duration, and rejects LOAD/EXPORT/DELETE for
those indices. PR1 therefore requires clearing the old Gate ghost library;
orphaned tail files are otherwise ignored. V3 SAVE never overwrites an
occupied row. The four sets of three reserved rows provide a 12-row policy
budget for one imported pool shared by all PB profiles: `4 * 45 + 12 = 192`,
equal to the former personal-row budget.

At 16 bytes per sample and one sample every four QF, raw recording costs about
479.5 bytes/s, 28.8 KiB/min, or 1.73 MiB/hour. Ten hours is about 17.3 MiB of
sample data per profile. Every SGHF V3 file also carries a fixed 2 KiB segment
table, at most 90 KiB across 45 live personal rows. Forty full 15-minute ghosts
reach the time quota; shorter new ghosts can fill all 45 writable rows.

Each active slot has two physical generations. The strict count-based bound for
45 maximum-size V3 files in both banks is 39,049,920 bytes (37.24 MiB) per
profile, 148.96 MiB per region, or 446.89 MiB across all three regions. The
ten-hour quota normally makes actual use lower. This is SD capacity, not
runtime memory.

The imported pool is count-bounded, not copied into the library and not charged
to a PB profile's ten-hour quota. Twelve 15-minute files expose at most three
hours and twelve maximum-size SGHF V3 files total 5,206,656 bytes (4.97 MiB).
Additional user-managed files may exist in the directory but are reported as
overflow and are not exposed until the lexical selection changes.

## Ownership protocol

The transfer mailbox uses immutable ownership:

1. The PPC waits for an idle/acknowledged sequence.
2. For a save, it writes and flushes the complete canonical payload first.
3. It then writes and flushes the PPC-owned request cache line.
4. ARM reads the request once and treats it as immutable until completion.
5. ARM processes at most one small catalog unit or 16 KiB payload chunk on one
   DI-idle main-loop pass.
6. ARM writes and flushes only its response cache line after payload I/O and
   validation are complete.
7. PPC invalidates the response line. For a load/list it invalidates the exact
   returned payload length before parsing it.

Only one request may be active. Unknown mailbox versions, unknown commands,
oversized lengths, bad profiles/slots, sequence reuse, and unsupported launchers
are rejected before payload access.

The save-confirmation name is bound to a stable logical-selection token. On A,
the storage bridge re-reads that identity immediately before synchronously
exporting the canonical bytes and refuses the save if it changed; the UI must
show the new name and require another confirmation. The separate per-sample
record revision returned by `exportLatest` remains the asynchronous ownership
token used only when acknowledging a completed SAVE.

Mailbox protocol V3 retains the 32-byte request and response records and the
fixed 128-byte catalog row. It adds virtual profile `4` for the global imported
namespace and distinguishes cached imported LIST from explicit IMPORT_SCAN.
The on-disk A/B envelope remains version 1. Canonical storage accepts only
SGHF V3; old SGHF V1/V2 files are recognized as unsupported and never decoded
or migrated. Mixed older/newer mod and launcher binaries fail the mailbox
version check rather than reinterpreting the virtual profile or command.

Personal commands remain LIST, SAVE, LOAD, DELETE, and EXPORT. Imported profile
`4` accepts LIST, IMPORT_SCAN, LOAD, and DELETE for rows `0..11`. LIST may
publish the ARM's current catalog (and performs the first scan lazily);
IMPORT_SCAN forces a new bounded directory enumeration. No external filename
crosses the mailbox. The ARM keeps only sanitized leaves and the PPC receives
metadata rows.

## Files and indexing

The launcher creates fixed directories on the device it was launched from:

`/susamune_ghosts/<region>/p<profile>`

It also creates the export paths under
`/susamune_ghosts/share/<region>/p<profile>` and the single user-facing import
root:

`/susamune_ghosts/import/`

EXPORT uses
`YYYY_MM_DD_<route>_<time>[<CRC>].smsghost`, for example
`2026_08_15_BH4_42490[89ABCDEF].smsghost`.

The kernel derives every filename from the validated numeric region/profile,
the export date, canonical route/duration fields, and the canonical file CRC.
Main-course routes use short names such as `BH4`; an internal start uses its
validated parent and route variant when present, and uncommon routes fall back
to bounded raw `AxxEyy`. Author, display name, and external filenames never
become export path components.

The kernel FatFS build uses `_FS_MINIMIZE=0` so imported enumeration and
explicit imported deletion are available. FatFS remains non-reentrant; every
call still runs only from the ghost branch after PB/config work and while no
async DI request is in flight. The fixed A/B journal mechanism is unchanged:

The current ARM link map attributes 2,972 bytes (`0xb9c`) of live text to the
newly reachable enumeration/delete path. Of that, 1,600 bytes are
`f_opendir`, `f_closedir`, `f_readdir`, `f_unlink` and their UTF-8 wrappers;
1,372 bytes are `get_fileinfo` and `dir_remove`. Other level-zero FatFS APIs
remain garbage-collected (zero-address discarded map entries), so merely
compiling them does not enlarge the final kernel image.

- LIST examines the two known generation names for each slot.
- SAVE writes the inactive/older generation with create-always semantics.
- DELETE writes a newer tombstone generation.
- An interrupted write leaves the previous complete generation readable.
- EXPORT uses `FA_CREATE_NEW`, then commits the friendly file's canonical
  header last. It never replaces an earlier export; an existing deterministic
  name is reported as already existing. This prototype does not compare the
  existing bytes or treat that response as a successful export.

An imported scan advances by one directory entry, open/read/close operation,
or other bounded FatFS unit per service pass. A leaf must be printable ASCII,
at most 95 bytes, free of FAT/path separators and reserved punctuation, not end
in dot/space, and end case-insensitively in `.smsghost`. Candidate leaves are
sorted case-insensitively with an exact-ASCII tie-break, and the smallest 12
compatible files populate packed rows `0..11`. FAT enumeration order therefore
cannot change which files appear. The response generation field carries the
bounded count beyond 12.

Those row numbers are lexical positions, not persistent file identities. A
forced scan immediately detaches the loaded-row association, and adoption of
any imported catalog does the same. Deleting the currently associated leaf
also clears its pinned playback; deleting another leaf leaves the already
decoded playback usable but unassociated because later rows may renumber. A
subsequent LOAD establishes a new association. The UI therefore never labels a
different file as the active race target after insertion, deletion, or rescan.

The scan validates the canonical header and V3 segment table before exposing a
row. LOAD reopens the sanitized leaf beneath the fixed import root and validates
every byte and CRC before activation. Imported files remain their own sources;
they are never copied, renamed, or committed into a personal A/B row. Explicit
DELETE unlinks only the selected cached leaf and invalidates the imported
catalog.

Friendly exports are unmanaged copies, not live journal entries. They do not
consume a slot or contribute to the 45-row/ten-hour library quota. Exporting
the same canonical object again on the same UTC/FAT date reports that its leaf
already exists without comparing bytes; a later date selects a new leaf, so
copies can accumulate.
This gate neither enumerates nor prunes exports. Full or write-protected media
fails the export and leaves both A/B generations unchanged; the in-memory
catalog may be invalidated and safely rescanned after an ambiguous I/O result.

Both personal LIST and imported scanning are incremental. They open and
validate at most one generation, entry, prefix, or equivalently bounded unit
per DI-idle service pass. A corrupt personal slot or rejected imported file
does not prevent unrelated valid ghosts from loading. A supported-version
import that passed the prefix scan but fails full payload or CRC validation
remains a visible unsafe row with its sanitized leaf, so it cannot race but can
still be explicitly deleted.

A recognised but unsupported personal file or envelope version is not treated
as empty. This includes old SGHF V1/V2 as well as future versions. The personal
slot becomes read-only/unsafe so the kernel cannot overwrite data it does not
understand. An unsupported imported file is omitted; if an already catalogued
leaf changes version, full LOAD invalidates the catalog and the required rescan
omits it without permitting deletion.
Invalid personal bytes without a recognised supported envelope are not treated
as occupied, but every recognised occupied row refuses SAVE. V3 has no
overwrite request or confirmation ABI.

## Validation

Both sides validate before committing state. Required checks include:

- mailbox, file, and codec magic/version;
- exact V3 header, fixed segment-table, sample offsets, and sizes;
- payload length no greater than `0x7ff00`;
- sample count within the 15-minute runtime capacity;
- duration within the per-ghost cap and consistent with sample deltas;
- every packed pose: big-endian signed 16-bit yaw, big-endian unsigned 16-bit
  QF delta, three signed 24-bit positions bounded to `+/-8,000,000` fixed units
  at 1/8-game-unit scale, animation ID `0..335`, any 12-bit normalized phase,
  and zero low three reserved animation bits;
- an exact recognized JP/US/PAL game-ID/region pair, revision zero, source
  profile `0..3`, route, and feature flags;
- bounded parent episode and route fields;
- strictly bounded author bytes with explicit termination/sanitisation;
- unused V3 extension and segment-table fields zero;
- header, payload, segment-table, and whole-file checksums;
- monotonically selected A/B generation;
- personal count and aggregate-duration quotas on SAVE.

Personal rows require the running game ID/region and selected profile exactly.
An imported file may originate from any of the three recognized regions.
Same-region imports use the ordinary structural route checks. A foreign-region
file is accepted only when its header route and every SGHF V3 segment route are
in the shared portable table in `ghost_format.h`, including the exact known
child-parent relationship. The ARM prefix scan, ARM full LOAD validator, PPC
catalog sanitizer, and PPC playback activation use that same policy. There is
no metadata rewrite and no claim that physics or object behavior is portable.

LOAD decodes into an inactive buffer and changes the active playback only after
the entire file validates. Failure leaves the current race target unchanged.

## Recording and race behaviour

The recorder samples Mario's collision transform plus a bounded animation ID
and normalized animation phase as a visual reference. It is not deterministic
input replay and makes no claim about RNG, enemies, objects, lag, savestates,
or practice-assist equivalence.

At a QFT attempt edge the ghost recorder first establishes the post-reset clock
epoch. Samples taken before a detected reset are tentative and are discarded
as a unit. Once stable, recording and playback use the unchanged QFT value as
their common timebase.

A completed valid recording remains the latest playback even when the next
scene has another route. Route matching gates visibility, not preservation, so
the user can still export the last attempt. A loaded library ghost may later be
pinned as the race target; in that mode subsequent attempts reuse the recording
buffer rather than replacing the selected playback.

Savestate load discards the volatile recording. A pinned library playback is
kept and resynchronizes against the restored QFT epoch; an unpinned volatile
playback is discarded. An already staged SAVE may safely finish because ARM
owns its immutable payload. A pending LOAD response is ignored after the
savestate epoch changes, preventing an old asynchronous result from appearing
in restored gameplay.

## Failure behaviour

- Full, write-protected, missing, or unmounted storage: report the FatFS status;
  retain all volatile tracks.
- Interrupted SAVE: previous A/B generation remains active.
- Ambiguous SAVE/DELETE I/O result: invalidate the in-memory catalog and rescan
  A/B or the import directory before accepting another mutation.
- Interrupted DELETE: previous ghost may remain; it is never half-deleted.
- Corrupt file: isolate the slot and preserve other catalog entries.
- Unsupported personal canonical version, old or future: refuse load, save,
  and delete.
- Unrecognized origin or a foreign route without proven shared semantics:
  omit/refuse it; never patch metadata to fit.
- More than 12 compatible imports: expose the deterministic first 12 and a
  bounded overflow count; never rely on FAT order.
- A frame that actually ran with fast-forward, or a savestate load: invalidate
  the current visual recording. Merely holding a suppressed bind does not.
- Power loss while no request is active: no SD write occurs.

## Explicit deferrals

SGHF V3 prioritises a raw, independently validated pose payload. A future codec
may add keyframes plus delta/RLE packets behind a feature flag, but raw files
are already small enough for the quota and avoid making the first storage build
depend on a complex decompressor.

Also deferred until the core survives console testing: deterministic input
replay, a second interactive Mario, cross-region format conversion or physics
simulation, automatic PB replacement, network sharing, Unicode/import
subdirectories, and Dolphin host-file I/O. Bounded ASCII drag-and-drop
`.smsghost` leaves and portable visual playback are implemented without
rewriting the source file. SGHF V3 represents bounded parent/secret transitions
as route segments on one absolute QFT timeline.
