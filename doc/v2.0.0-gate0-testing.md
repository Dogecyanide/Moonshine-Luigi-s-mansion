# V2.0.0 Gate 0 test build

**DIAGNOSTIC ONLY — GHOST SAMPLING BUILD.** Every diagnostic toast begins
with `GHOST TEST:`. This build does not modify QFT timing or capture state; it
only reads QFT values from the ghost subsystem.

This is an experimental Ghosts of Delfino feasibility build, not a release.
It starts from the exact V1.2.0 tested commit
`b6bc8747fa01f99ae8335390aaee6ddac768d4e8`.

## What is in this build

- A padding-free 512 KiB MEM1 mod region with a `0x82000` arena reserve.
- A volatile transform recorder sampled every four QF, about 29.97 Hz.
- One cyan, collisionless visual marker replaying the previous same-route
  attempt.
- A 15-minute cap. A capped recording remains usable through its final sample.
- UI settings for ghost visibility and 25%, 50%, 75%, or 100% opacity.

There is no SD ghost I/O, library, import/export, Mario model, animation,
deterministic input replay, or parent-to-secret route playback yet.

## Expected lifecycle

1. Cold boot and start a normal QFT attempt. The first attempt records but has
   no ghost to display. `GHOST TEST: recording started` confirms capture is
   armed, followed by `GHOST TEST: sample 2 recorded` once the track is valid.
2. Restart the same route. `GHOST TEST: previous attempt ready` appears and
   the prior attempt replays from QFT zero while the new attempt records.
3. Restart again. The attempt just completed replaces the displayed ghost.
4. Change Ghost display and Ghost opacity in the UI tab and confirm both take
   effect without reopening the stage.

The volatile ghosts are intentionally discarded on a savestate load, while
fast-forward is active, on an incompatible route change, or at power-off.
Savestate format version 11 also rejects older snapshots because the 512 KiB
arena reservation moves the stage heap.

## Required checks

Test PAL first, then JP and US after the lifecycle gate passes.

- Exercise Instant Restart and Full Restart at least five times each.
- Verify recording and playback track QFT across normal lag without changing
  QFT results, freeze timing, PBs, Records, or attempt counting.
- Confirm the marker is camera-independent, disappears behind the camera or
  outside the viewport, and never affects Mario or stage objects.
- Open every menu tab and all Creation editors while recording and replaying.
- Save and load a savestate ten times. The game must remain stable and the
  volatile ghost must disappear after each load.
- Hold each fast-forward bind. The ghost must disappear and stay disabled until
  the next QFT attempt.
- Enter and leave a secret or other child area. No stale same-stage ghost may
  appear there.
- Repeat the V1.2 Fast Text, parent/secret QFT, Shine, death, boss, reset-button,
  settings, PB, Records, and progress-persistence checks.

The previously tested 500 KiB pressure pad is not present in this build. The
historical padded build proved the staging copy and MEM1 reservation; this build
uses the space for normal code and leaves the unused remainder absent from the
blob.

## Current budgets

| Build | JP blob | US blob | PAL blob | 512 KiB free |
|---|---:|---:|---:|---:|
| Console | 132,000 | 131,844 | 131,924 | 392,224 / 392,380 / 392,300 |
| Dolphin | 133,476 | 133,280 | 133,416 | 390,748 / 390,944 / 390,808 |

Each 512 KiB runtime slot holds 32,768 fixed-size samples. The 15-minute cap
uses at most 26,974 samples, or 431,584 bytes. Console record, playback, and
reserved transfer slots reuse the 1.5 MiB loader-only disc buffer after boot;
Gate 1 now uses that third slot for bounded ARM/PPC file transfers.

The Dolphin prototype slots at `0x71000000-0x71180000` are compile-time
non-overlapping but have not yet been runtime-proven like the existing 16 MiB
`0x70000000` aperture. Treat a clean Dolphin boot plus several recorded
restarts as a separate memory-map gate before relying on Dolphin ghost results.

Gate 1 supersedes the original storage sketch with two simultaneous limits:
15 minutes per ghost, 48 indexed ghosts per PB profile, and 10 recorded hours
per profile. The count remains policy rather than a format or hardware limit;
see `v2.0.0-gate1-testing.md` for the implemented journal and quotas.
