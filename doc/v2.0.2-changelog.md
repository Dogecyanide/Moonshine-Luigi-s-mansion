# Susamune V2.0.2 "Ghosts of Delfino"

## English

V2.0.2 is the complete Ghosts of Delfino hotfix. It combines the ghost safety,
storage, playback, and IL fixes below. At source freeze, the Wii hardware
acceptance pass is still required; the build is not release-approved until every
required row in `v2.0.2-testing.md` passes.

### Ghost capture and rendering

- Fixed the Yoshi-mount crash caused by treating Sunshine's out-of-band rider
  animation sentinel as a normal Mario animation-table index. Unsupported poses
  now fail safely instead of reading beyond the retail table.
- New recordings use ghost format V4 and capture Yoshi mount/colour state plus
  held-object identity per sample. V4 keeps the V3 16-byte sample stride,
  15-minute limit, file-size ceiling, and MEM2 slot budget. Existing V3 ghosts
  remain readable; older builds safely reject V4 rather than misreading it.
- Race, Watch, and Watch 2 now render a real Yoshi for V4 rider samples. They
  also render the five ordinary held fruits: coconut, papaya, pineapple, durian,
  and banana. The fruit follows the ghost's right hand.
- Other held identities are still recorded when the V4 descriptor table can
  represent them, preserving data for later support, but are not cloned into the
  scene. Unknown, unsupported, missing, or overflowed identities fail closed:
  the attachment is hidden and playback continues without borrowing an
  unrelated live actor.
- `Ghost opacity` now uses a genuinely opaque render state at `100%`, including
  ghost attachments. `25%`, `50%`, and `75%` remain translucent.

### PB protection and storage

- Added `PB ghost save` to the Ghosts tab with exactly `Ask`, `Auto-Save`, and
  `Don't ask`. It defaults to `Ask` and persists per game region.
- In `Ask`, A opens the protected Personal-slot save flow. B continues the held
  action without saving, but keeps the completed in-memory ghost available as a
  race target. Loading an older savestate is the unavoidable exception because
  it restores the older volatile state; save first or cancel that load if the
  new ghost must survive.
- `Auto-Save` uses the first empty Personal slot and waits for the exact storage
  acknowledgement. A full library, unavailable storage, an error, or a timeout
  returns to `Ask` without overwriting a slot or releasing PB protection.
  `Don't ask` continues without a prompt and without immediately erasing the
  completed target.
- A full 45-slot Personal library is never overwritten. From the protected save
  flow, X opens `Delete ghost from SD?`; A confirms, B cancels. After the delete
  acknowledgement, the catalog refreshes and offers the newly empty slot.
  Ordinary Personal and Imported deletion uses the same explicit confirmation.
- A Personal catalog name containing only spaces now displays as
  `Unnamed ghost`. The file, duration, slot identity, and available actions are
  unchanged.

### Playback, navigation, and eligibility

- Watch camera anchoring now carries the retail smoothed vertical state with the
  invisible Mario anchor. Sustained climbs and descents no longer leave the
  camera below the ghosts until it points straight upward; this applies to
  Watch and Watch 2.
- An IL launched from Delfino Plaza now remembers its exact launch scene. Exit
  Area returns a dry Plaza launch to dry Plaza and a flooded Plaza launch to
  flooded Plaza instead of asking the retail shine resolver to choose episode 9.
  Non-Plaza launches keep retail Exit Area behavior, and Area Lock/Disable Warps
  precedence is preserved.
- Actual FLUDD emission invalidates Records/PB eligibility only for a selected,
  standalone Secret IL. Merely carrying FLUDD does not invalidate it. Red-coin
  ILs remain eligible even when they share the same secret scene, and full-level
  runs remain eligible when they enter a secret and use FLUDD.

  **Erratum:** later hardware testing found that the standalone Secret
  invalidation is not reliable and remains unenforced in V2.0.3.

The QFT implementation and time source, Records journals, achievement data,
savestate format, settings/binds ordering, and fixed ghost-storage capacities
are unchanged.

## 日本語

V2.0.2 は Ghosts of Delfino の ghost safety／storage／playback／IL 修正をまとめた完全版 hotfix
です。source freeze 時点では Wii 実機 acceptance test が未完了のため、
`v2.0.2-testing.md` の必須項目がすべて pass するまで release-approved ではありません。

### Ghost 記録／描画

- Yoshi 搭乗 animation の範囲外 sentinel を通常の Mario animation-table index として扱い、
  crash していた問題を修正しました。unsupported pose は retail table の外を読まず、安全に
  fallback します。
- 新しい記録は ghost format V4 です。V3 と同じ 16-byte sample、15 分上限、file-size 上限、
  MEM2 slot budget のまま、sample ごとの Yoshi 搭乗／色と held-object identity を保存します。
  既存 V3 は引き続き読め、旧 build は V4 を誤読せず安全に拒否します。
- Race／Watch／Watch 2 で V4 rider sample に実物の Yoshi model を描画します。通常の 5 種類の
  fruit（coconut、papaya、pineapple、durian、banana）も ghost の右手に追従して表示します。
- その他の held identity も V4 descriptor table に入る限り将来の対応用に記録しますが、scene
  には clone しません。unknown／unsupported／missing／overflow identity は別の live actor を
  誤使用せず、attachment だけを非表示にして playback を継続します。
- `Ghost opacity` の `100%` は attachment を含め本当に opaque な render state になりました。
  `25%`／`50%`／`75%` は従来通り translucent です。

### PB protection／storage

- Ghosts tab に `PB ghost save` (`Ask`／`Auto-Save`／`Don't ask`) を追加しました。default は
  `Ask` で、region ごとに保存されます。
- `Ask` の A は protected Personal-slot save flow を開きます。B は save せず held action を続行
  しますが、completed in-memory ghost は race target として残します。古い savestate の load は
  古い volatile state を復元するため唯一の例外です。ghost を残す場合は先に save するか load を
  cancel してください。
- `Auto-Save` は最初の空き Personal slot を使用し、exact storage ACK を待ちます。library 満杯、
  storage unavailable、error、timeout は overwrite／protection release をせず `Ask` に戻ります。
  `Don't ask` は prompt を出さず、completed target を即時削除せずに続行します。
- 45 Personal slot が満杯でも overwrite しません。protected save flow で X を押すと
  `Delete ghost from SD?` が開き、A で confirm、B で cancel します。delete ACK 後に catalog を
  refresh し、新しく空いた slot を提示します。通常 Personal／Imported delete も同じ明示
  confirmation を使います。
- spaces だけの Personal catalog name は `Unnamed ghost` と表示します。file、duration、slot
  identity、action は変更しません。

### Playback／navigation／eligibility

- Watch camera の非表示 Mario anchor と一緒に retail の smoothed vertical state も移動します。
  大きな上昇／下降で camera が下に取り残され、最終的に真上を向く問題を Watch／Watch 2 の両方で
  修正しました。
- Delfino Plaza から IL を開始した場合、正確な launch scene を記憶します。Exit Area は dry Plaza
  からなら dry Plaza、flooded Plaza からなら flooded Plaza に戻り、retail resolver が episode 9
  を誤選択しません。Plaza 以外からの開始は retail 動作のままで、Area Lock／Disable Warps の
  precedence も維持します。
- 実際の FLUDD emission は、選択した standalone Secret IL の Records／PB eligibility だけを
  invalidate します。FLUDD を持っているだけでは invalidate しません。同じ secret scene を使う
  Red-coin IL と、secret に入る full-level run は FLUDD を使っても eligible のままです。

  **訂正:** 後の実機テストで standalone Secret の invalidation が reliable でないことが判明し、
  V2.0.3 でも enforce されていません。

QFT implementation／time source、Records journal、achievement data、savestate format、既存の
setting／bind 順序、固定 ghost-storage capacity は変更していません。
