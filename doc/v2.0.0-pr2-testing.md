## Hard safety boundaries (English)

- Keep QFT visible for every timing test. PR2 must not change QFT timing,
  capture hooks, results, leading-zero behavior, or persistence. Any changed
  QFT value is a release-blocking failure.
- Ghosts remain visual-only and collisionless. The mod must never instantiate
  Shadow Mario enemy AI, collision, goop, damage, brush, or object logic.
- The retail Shadow assets are extracted at boot from the tester's own selected
  disc or ISO. They are not distributed in the package. Asset staging stays in
  a fixed 64 KiB tail of the record slot; the model stays in its fixed 88 KiB
  playback-slot heap. Recording capacity and the 15-minute limit must not move.
- If the retail model or its fixed heap cannot initialize safely, the cyan 2D
  marker is the required fallback. Ordinary or goopy Mario is never an
  acceptable fallback.
- Theme files are launcher-only. All image/audio buffers and audio services
  must stop and be freed before the game kernel starts. Themes must consume no
  game MEM1, MEM2, system heap, or stage heap.
- SD/FAT operations stay serialized behind the async-DI guard. Occupied ghost
  slots are never overwritten. Do not repeatedly issue an operation merely
  because a list or save is delayed.
- Savestates remain one slot and same-scenario only. Networking, emulator-style
  cross-stage states, and the 2.1 stage loader are not part of this build.

- すべての計測テストで QFT を表示してください。PR2 は QFT の計測、capture
  hook、結果、leading zero、保存動作を変更してはいけません。QFT の値が 1 つ
  でも変わった場合はリリースを止める重大な失敗です。
- ゴーストは見た目だけで、当たり判定を持ちません。Shadow Mario の敵 AI、
  collision、goop、damage、brush、object logic を生成してはいけません。
- 製品版 Shadow の asset は、テスター自身が選択した disc／ISO から起動時に
  抽出されます。パッケージには同梱しません。asset は record slot 末尾の固定
  64 KiB、model は playback slot 内の固定 88 KiB heap に置きます。記録容量と
  15 分上限が変化してはいけません。
- 製品版 model または固定 heap を安全に初期化できない場合、シアン色の 2D
  marker へフォールバックするのが正常です。通常 Mario や goopy Mario を

- savestate は引き続き 1 slot、同一 scenario 専用です。networking、emulator

1. On PAL first, record and race a short ordinary-stage ghost. The 3D visual

   goop, clothing, shading, or materials.
2. Stand still, spin, talk to an NPC, spray, hang, swim, and change Mario's
   state while the ghost moves. The ghost may use approximate locomotion, but
   it must not copy the live player's current pose frame-for-frame.
3. Test 25%, 50%, 75%, and 100% Ghost opacity while overlapping Mario, behind
   scenery, in fog/water, and during hotel/casino/secret transitions. The
   entire Shadow silhouette must change opacity monotonically. Opacity must not
   control goop, dirt, only one material, or only the cyan fallback.
4. Exercise Bianco, Ricco, Gelato, Pinna, Sirena, Noki, Pianta, plaza, secrets,
   bosses, and a stage that already uses Shadow Mario. Missing stage-local
   resources must not matter when boot staging succeeded. If initialization
   fails, report the exact route and confirm the cyan marker remains synced.
   CISO and WiiVC extraction are not supported in this prototype, so a synced
   cyan fallback is expected for those sources. Dolphin has no launcher staging:
   it uses native Shadow only in stages that already mount the resource and
   uses the synced cyan fallback elsewhere.
5. Repeat Full Restart, Instant Restart, pause, warp, Shine, death, savestate
   load, and 30 consecutive stage transitions. The model must reinitialize
   without a stale pointer, crash, increasing stage/system heap use, or damage
   to the fixed sample/segment regions.
6. Race an imported ghost and complete a challenger. The challenger may remain
   saveable through Delfino Plaza and related child segments. Enter a different
   non-hub course: the irrelevant target must auto-unpin, the completed
   challenger must be preserved, and the new course must immediately begin
   recording. The old Gelato-style save source must not persist for ten levels.
7. Repeat step 6 with personal/imported targets, partial/completed challengers,
   child-start ghosts, and an in-flight save acknowledgement. The confirmation
   name, stored bytes, and current recorder must never exchange identities.
8. Build the two-buffer case: leave unsaved playback ghost A retained, then
   make current challenger B valid. Request a course from the IL tab, Warp
   Wheel, instant chart, and Warp Last. Because the reset promotes B over A,
   each prompt must name A. Controller B must cancel and leave the stage and
   both ghosts untouched; controller A must use the unchanged destination. If
   the victim identity changes, the warning must refresh and require another
   confirmation. Saving A first
   must remove the warning. With only current ghost B and no unsaved playback,
   the same warp must not show a false warning because B is promoted, not
   discarded. Repeat through retail Exit Area; its QFT reset must make the same
   ownership decision before Plaza loads. Route-preserving restart commands do
   not warn; an explicit same-route course warp warns only if a different
   unsaved playback would really be replaced. Confirm that
   A/B never fires a savestate, action, menu bind, or second warp. Finally hold
   a chart selector only during an already-finished ordinary exit: if it would
   discard a ghost, the redirect must be refused with a save-first notice and
   the retail destination must load normally. Repeat with the card worker busy
   and challenger B still inside its clock-sync window when the warp is armed.
   If B becomes valid during the delay, the warning must appear before the
   departure; cancelling it must also cancel a newly selected IL attempt.
   While a guarded arm waits on card I/O, load a savestate and, separately,
   enable Disable warps. Both must cancel the old arm and restore temporary IL
   state; the warp must never fire later. Reopen the menu during the delay and
   change FLUDD in secrets. Cancellation must preserve that manual choice, and
   the final settings acknowledgement and reboot must retain the final value.
