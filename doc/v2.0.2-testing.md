# Susamune V2.0.2 "Ghosts of Delfino" Testing / テストガイド

## English

This is the required Wii hardware acceptance matrix for V2.0.2. At source
freeze it is still pending: do not publish or call the build accepted until all
required rows pass. Back up `susamune.ini`, Records/PB data, Personal and
Imported ghost folders, theme assets, and BGM. Install all eight files from one
package together. Homebrew Channel and the launch screen must both show
`Susamune Launcher`, `V2.0.2 "Ghosts of Delfino"`, and one matching Build ID.

Record the console region, source (disc/SD/USB), result, and any crash-log pair
for every row. JP is the primary full pass; the explicitly marked US and PAL
rows are required region smokes.

### Gate 1: Yoshi crash, V4, and real attachments

1. **JP, original reproducer:** replay the ghost that produced
   `susamune_crash_b.txt`, reach every Yoshi-mount frame, and finish or exit the
   playback. Race, Watch, and Watch 2 must not DSI. If this legacy file predates
   V4 attachment metadata, a safe rider/marker fallback is acceptable; it cannot
   be expected to reconstruct a Yoshi that was never recorded.
2. **US and PAL smoke:** record, save, reload, and Race or Watch one Yoshi run on
   each region. Also replay one established V3 ghost. No region may crash, and
   V3 playback must remain unchanged and attachment-free.
3. **Yoshi matrix, JP:** make fresh V4 recordings for green, orange, purple, and
   pink Yoshi wherever each colour is reachable, then replay them in Race,
   Watch, and Watch 2. The rider and a real Yoshi must remain visible; check
   mount/dismount boundaries, rider pose, colour, position, and that a two-ghost
   mix can show two independent Yoshi states without the cyan marker fallback.
4. **Fruit matrix, JP:** separately hold coconut, papaya, pineapple, durian, and
   banana while recording. Save/reload each file, then exercise Race, Watch, and
   Watch 2. The correct fruit must follow the correct ghost's right hand; switching
   between held identities or releasing one must not retain a stale fruit.
5. **Fail-closed matrix:** record at least one non-fruit takeable actor,
   one identity whose source actor is absent during replay, and, where a safe
   route permits, more distinct identities than the V4 descriptor table holds.
   The recording must remain valid. Unsupported/missing/unknown attachments must
   be hidden without a crash, bogus fruit, or borrowed live actor.
6. Validate new files with `scripts/validate_ghost.py`: they must be V4 with
   valid attachment metadata. Corrupt attachment indexes/flags must be rejected,
   and an established V3 file must still validate and play.

### Gate 2: opacity and Watch camera

1. Test `Ghost opacity` at `25%`, `50%`, `75%`, and `100%` with Mario,
   Piantissimo, Yoshi, and a fruit visible. The first three must remain
   translucent. At `100%`, all visible ghost geometry must be fully opaque, not
   merely alpha 255 through a translucent blend state.
2. Watch one ghost through a sustained climb and descent. Repeat with Watch 2,
   first close together and then widely separated vertically. The camera may
   retain retail horizontal compromises, but vertical lag must not accumulate or
   leave it pointing straight upward.
3. Repeat direct-secret and parent-to-secret Watch 1/2, including B and Start
   cutscene skips. Finish naturally, exit with fresh B and fresh Start, and force
   one safe route failure. Each path must restore a visible, controllable Mario
   and normal camera without a permanent vertical offset.

### Gate 3: PB save policy and volatile-target behavior

1. Confirm `PB ghost save` offers exactly `Ask`, `Auto-Save`, and `Don't ask`,
   defaults to `Ask`, and persists independently for JP, US, and PAL.
2. In `Ask`, create a PB and trigger each protected departure class: restart,
   Exit Area, natural stage departure, return-to-title, and savestate load. A
   must open the exact PB Personal save flow. For every action except savestate
   load, return and press B: the held action must continue without saving and the
   completed track must remain selectable as the PB race target. A savestate load
   may discard that newer volatile target only because the older state is restored;
   verify cancel/save-first is available instead.
3. With two protected PB tokens, resolve one at a time using both A and B paths.
   Neither response may silently resolve or overwrite the other target.
4. In `Auto-Save`, create a PB with an empty Personal slot. It must use the first
   empty slot, wait for that request's success ACK, and only then continue. Test
   storage error, timeout/unavailable storage, and a fresh B during the wait; each
   must return to `Ask` with the PB/action still protected.
5. In `Don't ask`, repeat restart, Exit Area, and natural departure. No prompt may
   appear, no existing slot may be written, and the completed race target must not
   be immediately erased.
6. Repeat the Ask and Auto-Save Exit paths with Disable Warps on, then repeat
   Exit/restart with Area Lock on and Disable Warps off. No modal may lock. Area
   Lock must restart the area after confirmation; Disable Warps must preserve
   the existing confirmed retail Exit while mod restarts remain disabled.

### Gate 4: full library, deletion, and blank names

Use only a backed-up or expendable ghost library.

1. Fill or stage all 45 writable Personal slots. A protected `Auto-Save` must
   fall back to `Ask`; it must never overwrite an existing slot.
2. In the protected full-library browser, select several slots and press X.
   `Delete ghost from SD?` must appear for the selected slot. B must cancel with
   no file/catalog mutation.
3. Repeat and press A. Wait for the exact delete ACK. The catalog must refresh,
   offer that same newly empty slot, and still require a separate A to save the
   protected PB. Confirm neighboring files are byte-identical.
4. Repeat X/A and X/B in ordinary Personal and Imported browsing. Unsafe
   Personal entries must stay immutable. Quarantined or forward-version Imported
   entries must stay visible and become removable only after confirmation.
5. Load a Personal header whose non-empty display name contains spaces only. Its row
   must read `Unnamed ghost` while retaining the correct number, duration, colour,
   selection, Race/Watch/save-target behavior, and confirmed-delete target.

### Gate 5: exact IL return and Secret FLUDD eligibility

Erratum: the standalone Secret invalidation rows below failed later hardware
acceptance and remain a known issue in V2.0.3.

1. From a normal/dry Delfino Plaza scene, launch a selected IL, then use Exit
   Area. It must return to that exact dry Plaza scene, not flooded episode 9.
2. From flooded Plaza, launch the same IL and Exit Area. It must return to the
   exact flooded launch scene. Repeat both rows after a PB prompt A/save and
   B/continue path.
3. Launch an IL without a Plaza source and Exit Area; retail destination behavior
   must remain intact. Repeat the dry-Plaza row with Area Lock enabled (restart
   current area) and with Disable Warps enabled (confirmed Exit still completes).
4. Select a standalone `Secret` IL. Complete one clean control run without FLUDD
   emission; it must remain Records/PB eligible. Repeat and emit any FLUDD nozzle
   at least once; that attempt must become ineligible. Merely carrying FLUDD must
   not invalidate the control.
5. Select a Red-coin IL that uses the same secret scene. Use FLUDD and beat its
   comparison time; the Red attempt must remain Records/PB eligible.
6. Select a full-level route that enters a secret. Use FLUDD before and/or inside
   the child scene and beat its comparison time; the full-level attempt must
   remain eligible. Save/load or replay each resulting eligible ghost to ensure
   eligibility logic did not corrupt capture.

### Gate 6: release regressions

1. Enter Bianco 4, Bianco 5, and Pianta 5 through retail Shine Select. Also smoke
   Ricco 8, Pinna 7, Noki 3, and Sirena 1.
2. Recheck ordinary Race/Watch/Watch 2, Shadow Mario and Piantissimo ghosts,
   ghost deletion, lifetime ghost statistics, QFT timing, Records, achievements,
   Warp Wheel, instant/full restart, savestate save/load, theme/BGM, and existing
   JP/US/PAL settings.
3. Confirm no temporary ghost diagnostics or model-loader test labels are visible.
   Confirm the package contains exactly the intended eight launcher files and its
   bundled `TESTING.md`/`CHANGELOG.md` identify V2.0.2.

If the Wii raises a hard exception, leave the crash screen visible for about five
seconds before power-off. Preserve the newest matching
`susamune_crash_a.txt/.bin` or `susamune_crash_b.txt/.bin` pair from the root of
the device that launched Susamune, and mark that matrix row failed.

## 日本語

これは V2.0.2 の必須 Wii 実機 acceptance matrix です。source freeze 時点では未完了なので、全必須
row が pass するまで公開／accepted 扱いにしないでください。`susamune.ini`、Records／PB、Personal／
Imported ghost folder、theme、BGM を backup し、同じ package の 8 files を一緒に導入します。Homebrew
Channel と launch screen の両方が `Susamune Launcher`、`V2.0.2 "Ghosts of Delfino"`、同じ Build ID
を表示することを確認します。各 row で console region、disc／SD／USB、結果、crash-log pair を記録
してください。JP は full pass、明記した US／PAL row も必須です。

### Gate 1: Yoshi crash／V4／実物 attachment

1. **JP original reproducer:** `susamune_crash_b.txt` を発生させた ghost を Race／Watch／Watch 2 で
   Yoshi mount frame まで再生し、finish または exit します。DSI が出ないこと。V4 attachment metadata
   より古い file は、記録されていない Yoshi を復元できないため safe rider／marker fallback でも
   構いません。
2. **US／PAL smoke:** 各 region で Yoshi run を record、save、reload、Race または Watch します。
   既存 V3 ghost も再生し、crash せず従来通り attachment なしで動くこと。
3. **JP Yoshi matrix:** 到達可能な green／orange／purple／pink Yoshi を fresh V4 で記録し、Race／
   Watch／Watch 2 で確認します。cyan marker ではなく rider と実物 Yoshi が見え、mount／dismount、
   rider pose、色、位置、2 ghosts が別々の Yoshi state を表示できること。
4. **JP fruit matrix:** coconut、papaya、pineapple、durian、banana を個別に持って record／save／reload
   し、Race／Watch／Watch 2 を実行します。正しい fruit が正しい ghost の右手に追従し、持ち替え／
   release 後に stale fruit が残らないこと。
5. **Fail-closed:** non-fruit takeable actor、replay 時に source が存在しない identity、可能なら V4
   descriptor table 数を超える identity を記録します。file は valid のまま、unsupported／missing／
   unknown attachment が crash、偽 fruit、別の live actor にならず非表示になること。
6. `scripts/validate_ghost.py` で新規 V4 metadata と既存 V3 を検証し、破損 index／flag は拒否される
   こと。

### Gate 2: opacity／Watch camera

1. Mario、Piantissimo、Yoshi、fruit が見える状態で `25%`／`50%`／`75%`／`100%` を確認します。
   最初の 3 つは translucent、`100%` は alpha 255 の blend ではなく完全 opaque であること。
2. 大きく上昇／下降する route を Watch 1／2 で確認し、2 ghosts を近く／上下に離した場合も vertical
   lag が累積して真上を向かないこと。
3. direct secret／parent-to-secret、B／Start intro skip、natural finish、fresh B／Start exit、safe
   failure を確認し、visible／controllable Mario と offset のない通常 camera が戻ること。

### Gate 3: PB save policy／volatile target

1. `PB ghost save` が `Ask`／`Auto-Save`／`Don't ask` の 3 choice、default `Ask` で、JP／US／PAL
   ごとに保存されること。
2. `Ask` で PB 後に restart、Exit Area、natural departure、title、savestate load を個別に開始します。
   A は exact PB save flow を開くこと。savestate load 以外は戻って B を押すと save せず action を
   続行し、completed track が PB race target として残ること。savestate load は古い volatile state
   を復元するため唯一 target を失ってよい path で、cancel／save-first が選べること。
3. protected PB token 2 個を A／B の両方で 1 個ずつ処理し、もう一方を silent resolve／overwrite
   しないこと。
4. `Auto-Save` は最初の空き Personal slot に exact success ACK 後だけ続行します。storage error、
   timeout／unavailable、wait 中の fresh B は PB／action を保持して `Ask` に戻ること。
5. `Don't ask` で restart／Exit／natural departure を行い、prompt／slot write がなく completed race
   target を即時削除しないこと。
6. Disable Warps on の Ask／Auto-Save Exit と、Area Lock on＋Disable Warps off の Exit／restart を
   確認し、modal lock しないこと。Area Lock は confirmation 後 restart、Disable Warps は mod restart
   を無効のまま保ちつつ confirmed retail Exit を swallow しないこと。

### Gate 4: library 満杯／delete／blank name

backup 済みまたは expendable library のみを使用します。

1. 45 Personal slot を満杯にし、protected `Auto-Save` が overwrite せず `Ask` に戻ること。
2. protected browser で X を押すと selected slot の `Delete ghost from SD?` が出て、B は file／catalog
   を変更せず cancel すること。
3. X 後 A を押し exact delete ACK を待ちます。catalog refresh 後に同じ空き slot を提示し、PB save
   には別の A が必要で、隣の file が byte-identical であること。
4. 通常 Personal／Imported でも X/A と X/B を確認します。unsafe Personal は immutable、
   quarantined／future-version Imported は visible のまま confirmation 後だけ削除可能であること。
5. non-empty spaces-only name の Personal header が `Unnamed ghost` と表示され、number、duration、
   colour、selection、Race／Watch／save target／confirmed-delete target が正しいこと。

### Gate 5: exact IL return／Secret FLUDD eligibility

訂正: 下記 standalone Secret invalidation row は後の実機 acceptance で fail し、V2.0.3 でも
known issue のままです。

1. normal／dry Delfino Plaza から IL を開始して Exit Area し、flooded episode 9 ではなく exact dry
   launch scene に戻ること。
2. flooded Plaza から同じ IL を開始して exact flooded launch scene に戻ること。両方で PB prompt の
   A/save と B/continue を再確認します。
3. Plaza 以外から開始した IL の retail Exit destination、dry Plaza＋Area Lock の current-area restart、
   Disable Warps 時の confirmed Exit completion を確認します。
4. standalone `Secret` IL は FLUDD emission なしなら Records／PB eligible、任意 nozzle を 1 回でも
   emit した attempt は ineligible、FLUDD を持つだけなら eligible であること。
5. 同じ secret scene の Red-coin IL は FLUDD 使用後に comparison time を更新しても Records／PB
   eligible のままであること。
6. secret に入る full-level run も child scene の前／中で FLUDD を使用して eligible のままである
   こと。eligible ghost を save／load または replay し、capture が壊れていないこと。

### Gate 6: release regression

retail Shine Select から Bianco 4／5、Pianta 5、さらに Ricco 8、Pinna 7、Noki 3、Sirena 1 を smoke
test します。通常 Race／Watch／Watch 2、Shadow Mario／Piantissimo、delete、lifetime stats、QFT、
Records、achievement、Warp Wheel、restart、savestate、theme／BGM、JP／US／PAL settings を再確認し、
一時 ghost diagnostic／model-loader label がないこと。package が意図した 8 files だけを含み、bundled
`TESTING.md`／`CHANGELOG.md` が V2.0.2 であること。

hard exception 時は約 5 秒待って power-off し、launcher device root の最新
`susamune_crash_a.txt/.bin` または `susamune_crash_b.txt/.bin` pair を保存して、その row を failed
と記録してください。
